## 1. 需求背景与目标

### 1.1 业务背景

美妆类目店铺的售后接待中，存在一批**高风险会话**（不良反应、过敏就医、疑似假货、舆情威胁等）。这类会话有三个特征：**判断依赖专业知识**（客服新手看不出"泛红刺痒"背后是化妆品不良反应）、**处置有合规红线**（不能随意承诺赔偿、不能说"这是过敏"这类医疗定性）、**时机敏感**（拖延或说错话会升级为平台投诉与舆情）。

千牛工作台的**右侧辅助区**是官方明确的产品扩展区域（智能客服面板所在位置，支持商家订购三方服务或接入自研服务）。本产品在该区域为客服提供**会话风险识别 + 决策辅助 + 话术约束**，定位是"在不干扰核心聊天流程的前提下，给客服即时的决策辅助"——与官方对该区域的产品定位一致。

产品分两个视角：**坐席视角**（工作台右侧四 Tab 辅助面板）与**主管视角**（独立风险看板，监控全店铺高风险会话）。

### 1.2 需求目标

| 目标类型 | Badge样式 | 目标描述 |
|:---------|:---------|:---------|
| **业务目标** | bg-purple-100 text-purple-700 | 高风险会话（critical/high）识别后 5 分钟内被人工接管的比例 ≥80%；因话术不当升级的售后投诉量下降 20% |
| **用户体验** | bg-blue-100 text-blue-700 | 选中会话后 1 秒内展示风险面板；AI 回复建议生成 ≤5 秒；全程不遮挡聊天区、不改变客服既有操作习惯 |
| **安全目标** | bg-red-100 text-red-700 | 危急/高危会话**不生成自由话术**，只输出处置要点；AI 生成内容 100% 携带"仅供参考"标识；不输出医疗定性与赔偿承诺 |

### 2.1 风险场景分类

会话经 S1 意图识别节点归类到以下场景大类（共 10 大类 / 41 小类，小类由数据字典维护）：

| 场景大类 | 权重基准 | 判定要点 | 数据来源 |
|---------|:---:|---------|---------|
| 不良反应 | 最高 | 泛红/刺痒/就医/疹子等身体反应词 | S1 意图识别（大模型 JSON 输出） |
| 舆情/投诉威胁 | 最高 | 12315、曝光、媒体、 Black 猫投诉等词 | S1 + 规则引擎关键词命中 |
| 疑似假货/正品质疑 | 高 | 假货、正品、吊牌、防伪 | S1 |
| 大额/催发风险 | 高 | 大额订单超时未发、买家情绪升级 | 订单数据 + S2 风险节点 |
| 退换货纠纷 | 中 | 退货理由与政策冲突 | S1 |
| 物流异常 | 中 | 破损、丢失、长时间未更新 | 物流数据 + S1 |
| 价格争议 | 中 | 买贵、降价、保价诉求 | S1 |
| 普通咨询 | 低 | 使用方法、色号推荐等 | S1 |
| 营销/推销识别 | 低 | 买家侧推销、广告话术 | S1 |
| 其他/无法归类 | 兜底 | 未命中任何小类 | S1 兜底分支 |

### 2.2 风险等级定义

会话综合风险由 S2 风险计算节点按场景权重 + 规则命中数（0-40 分制，`risk_count`）得出：

| 风险等级 | 分值区间 | Badge样式 | 行为影响 |
|---------|:---:|---------|---------|
| 危急 critical | 40 | bg-red-100 text-red-700 | 锁定话术（`locked=true`），只输出 AI 处置要点；看板置顶；建议主管介入 |
| 高危 high | 30–39 | bg-orange-100 text-orange-700 | 同危急：锁定话术，只给处置要点 |
| 中危 medium | 15–29 | bg-yellow-100 text-yellow-700 | 生成三档语气话术，置信度按证据完整度分级 |
| 低危 low | 1–14 | bg-blue-100 text-blue-700 | 生成三档语气话术 |
| 无 none | 0 | bg-gray-100 text-gray-700 | 面板只展示会话洞察与客户全景，回复建议 Tab 显示"暂无风险，正常接待" |

> **注意**：本模块的"危急/高危/中危/低危"是**会话风险等级**，与平台通用消息预警命名无关，仅在本产品内使用。

### 2.3 AI 回复建议的三档语气

| 语气 | tone值 | 适用场景 | 置信度来源 |
|------|------|---------|-----------|
| 专业 | professional | 涉及售后流程、赔偿政策的正式沟通 | 证据完整度 + 模型自评 |
| 亲切 | warm | 情绪安抚、日常关怀 | 同上 |
| 简洁 | concise | 高频快问快答 | 同上 |

生成约束（写死在提示词，不可被会话内容绕过）：不得编造事实、不得承诺赔偿金额/时限/责任认定、不得使用医疗定性表述、不得使用绝对化用语。

## 5. 功能清单

### 5.1 操作定义

| 操作 | 前置条件 | 生效时间 | 副作用 |
|------|---------|---------|--------|
| 标记已处置 | 会话存在未处置风险事件 | 即时 | 该会话全部风险事件状态→已处理；看板"待处置"数减少 |
| 复制建议话术 | suggestions 非空 | 即时 | 写入剪贴板，Toast"已复制" |
| 认领会话 | 会话状态=待接入 | 即时 | 会话状态→处理中，指派当前客服 |
| 刷新建议 | 会话未关闭 | 重新生成 | 重新调用模型（计一次模型调用） |

## 6. 异常与边界场景

| 场景 | 触发条件 | 系统反馈 | 恢复方式 |
|------|---------|---------|---------|
| 模型超时/失败 | 大模型响应 >15s 或 5xx | 接口返回 200 + `fallback=true` + 降级原因，面板展示规则命中的风险要点 | 客服点"刷新建议"重试 |
| JSON 输出非法 | 模型返回含围栏/前言导致解析失败 | 同上（自动重试 1 次后降级） | 同上 |
| 会话无风险数据 | 该会话未命中任何场景 | 洞察 Tab 显示"暂无风险，正常接待"空态 | 无需操作（正常态） |
| 会话已关闭 | 会话 status=4 | 回复建议 Tab 显示"会话已关闭——不再生成回复建议"空态，**不调用模型** | 新建会话或从工单发起联系 |
| 证据不一致 | 事件证据与会话上下文矛盾 | 列表"证据不一致"标记点亮（黄色），提示人工复核 | 主管人工判断 |
| 数据加载失败 | 网络异常/服务不可用 | 面板区域空态 + Toast"数据加载失败" | 重新选中会话触发刷新 |

## 7. 非功能需求

| 指标 | 要求 | 说明 |
|------|------|------|
| 风险面板首屏 | ≤1秒 | 选中会话到洞察/全景渲染完成 |
| 建议生成延迟 | ≤5秒 | 实测均值 3.6s（doubao-seed-2-1-turbo，thinking 关闭） |
| JSON 结构化输出成功率 | ≥99% | 探针实测 3/3=100%，需持续监控 |
| 已关闭会话建议请求 | 0 次模型调用 | 前端不发请求 + 后端兜底双重拦截（实测 0.06s 返回） |
| 风险数据更新 | 会话结束前的消息准实时进入下一轮计算 | 管道按批次导入 |
| 数据保留 | 会话与风险事件数据保留 6 个月 | 满足售后回溯 |

## 8. 验收标准

1. 给定一个归类为"不良反应"且分值 40 的会话，当客服选中该会话，则回复建议 Tab 在 5 秒内展示锁定态：话术区为空、AI 处置要点列表可见、面板含"仅供参考"标识
2. 给定一个中危会话（分值 15–29），当客服请求建议，则返回恰好 3 条建议且 tone 依次为 professional/warm/concise，每条均含 rationale
3. 给定一个已关闭会话，当客服选中并切到回复建议 Tab，则不产生任何大模型调用（接口响应 <200ms）且显示"会话已关闭"空态
4. 给定模型返回带 Markdown 围栏的非法 JSON，当解析失败，则自动重试 1 次后接口仍返回 200，`fallback=true`，面板展示降级原因
5. 给定主管在风险看板，当点击"标记已处置"，则该会话下全部风险事件状态变为已处理且顶部统计卡的"待处置"数同步减少
6. 给定买家会话中出现"再不解决就打 12315"，当 S1/S2 完成计算，则该会话综合风险 ≥ 高危（30 分）且命中词"12315"出现在证据中

## 9. 名词统一字典

| 名词 | 定义说明 | 数据来源 |
|------|---------|---------|
| 会话洞察 | 右侧面板第一个 Tab，展示风险等级与风险事件明细 | cs_session_context / cs_risk_event 表 |
| 客户全景 | 买家维度的聚合画像（访问次数/累计消费/工单/敏感标签） | 客户聚合数据 |
| 处置要点 | 高危会话下 AI 生成的内部动作指引（非买家话术） | 模型输出 evidence 字段 |
| locked | 布尔标记，true 时话术区强制为空、仅展示处置要点 | 建议接口响应 |
| fallback | 布尔标记，true 表示本次建议由规则降级生成而非模型 | 建议接口响应 |
| 证据不一致 | 规则命中的风险点与会话上下文相互矛盾的标记 | cs_risk_event.evidence_mismatch |
| S1/S2/S3 | 流水线三节点：意图识别 / 风险计算 / 建议生成 | 服务端 AI 编排 |
| 标记已处置 | 主管操作，将某会话全部风险事件置为已处理 | POST /cs-risk/handle |
